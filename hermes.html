ใช้ NemoClaw และ Hermes Agent

คนละระบบกับ Open WebUI Hermes อยู่ใน sandbox แยก ทำได้ทั้งคุย เรียกเครื่องมือ ตั้ง cron และรับงานจาก Telegram ภาพด้านล่างแคปจากแดชบอร์ดจริงบนเครื่องนี้

สองโปรแกรมนี้ต่างกันยังไง

NemoClaw

ตัวจัดการ sandbox เปิด ปิด ดูสถานะ ซ่อม gateway และพิมพ์ URL แดชบอร์ด คำสั่งบนเครื่องนี้คือ nemoclaw ชื่อ sandbox คือ hermes

Hermes Agent

เอเจนต์จริงที่อยู่ใน sandbox เวอร์ชันบนเครื่องนี้คือ 0.19.0 มีแดชบอร์ด Chat / Sessions / Files / Cron / Skills รันงานเองได้

nemohermes คือคำสั่งชุดเดียวกับ nemoclaw บนเครื่องนี้ ใช้ตัวไหนก็ได้ แนะนำใช้ nemoclaw ให้ตรงกับที่ระบบลงไว้

อย่าสับสนกับ Open WebUI ที่พอร์ต 18473 อันนั้นคือแชทธรรมดา Hermes คือเอเจนต์ในกรง sandbox

ขั้นที่ 1 ตรวจสถานะ

  1. เปิดเทอร์มินัลบนเครื่อง DGX

    กด Ctrl + Alt + T

  2. ดูภาพรวมทุก sandbox
    nemoclaw status
  3. ดูรายการ sandbox
    nemoclaw list

    ต้องเห็น hermes * ดาวหมายถึงเป็นค่าเริ่มต้น

  4. ตรวจสุขภาพแบบละเอียด
    nemoclaw hermes doctor

    ถ้าสรุปท้ายสุดเป็น Summary: healthy แปลว่าระบบหลักปกติ

ขั้นที่ 2 เปิดแดชบอร์ด

  1. พิมพ์หา URL ถ้าจำไม่ได้
    nemoclaw hermes dashboard-url
  2. เปิดเบราว์เซอร์บนเครื่อง DGX
  3. ไปที่ที่อยู่นี้แล้วกด Enter

    http://127.0.0.1:18789/

    หน้าต่างนี้ฟังที่ 127.0.0.1 เท่านั้น จากมือถือในบ้านเข้าตรง ๆ ไม่ได้

  4. ดูว่าขึ้นหัวข้อ HERMES AGENT มุมซ้ายบน

    มุมล่างซ้ายต้องมี Gateway Status: Running

ขั้นที่ 3 รู้จักหน้าจอ

เมนูซ้ายแต่ละอันมีหน้าที่คนละอย่าง จำไอคอนในแถบซ้ายของภาพจริงด้านล่าง

ขั้นที่ 4 คุยใน Chat

  1. คลิก CHAT ทางซ้าย
  2. ดูมุมขวาบนว่ามีป้าย live

    ต้องเห็นชื่อโมเดลและจุดเขียว live

  3. คลิก New chat ถ้าอยากเริ่มห้องใหม่
  4. คลิกช่องพิมพ์ด้านล่าง แล้วพิมพ์ข้อความ

    หน้าจอจริงมีคำใบ้เช่น explain this codebase

  5. กด Enter เพื่อส่ง
  6. รอคำตอบในพื้นที่สีดำตรงกลาง

    เอเจนต์มีเครื่องมือ เช่น อ่านไฟล์ รันโค้ด และค้นใน sandbox ไม่ใช่แค่พิมพ์ตอบ

ขั้นที่ 5 ดูเซสชันและ Telegram

  1. คลิก SESSIONS ทางซ้าย
  2. ดูกล่อง CONNECTED PLATFORMS

    บนเครื่องนี้มี api_server และ telegram สถานะ Connected

  3. ดู RECENT SESSIONS

    ห้องที่มีป้าย telegram คือคุยผ่านบอท ห้องที่เป็น cron คืองานตามเวลา

  4. คลิกห้องเพื่อเปิดต่อใน Chat
Telegram ถูกตั้งไว้แล้วบนเครื่องนี้ ไม่ต้องใส่ token ใหม่ถ้ายังใช้บอทเดิม อย่าแปะ token ลงเทอร์มินัลหรือคู่มือ

ขั้นที่ 6 คำสั่งที่ใช้บ่อย

พิมพ์ในเทอร์มินัลบนเครื่อง DGX ชื่อ sandbox คือ hermes

คำสั่งทำอะไร
nemoclaw statusภาพรวมทุก sandbox
nemoclaw listรายการ sandbox และ URL แดชบอร์ด
nemoclaw hermes statusสถานะ sandbox นี้ รวมเส้นโมเดล
nemoclaw hermes doctorตรวจสุขภาพทีละชั้น
nemoclaw hermes dashboard-urlพิมพ์ URL แดชบอร์ด
nemoclaw launch hermesต่อเข้า sandbox แล้วสตาร์ทเอเจนต์
nemoclaw hermes connectเปิดเชลล์เข้าไปใน sandbox
nemoclaw hermes logs --tail 50ดูล็อกล่าสุด
nemoclaw hermes stopหยุดคอนเทนเนอร์ แต่เก็บงานไว้
nemoclaw hermes startเปิด sandbox ที่หยุดไว้กลับมา
nemoclaw hermes recoverซ่อม gateway และพอร์ต forward
อย่าใช้ nemoclaw hermes destroy ถ้ายังอยากเก็บ sandbox นี้ คำสั่งนั้นลบทั้งกรง

ขั้นที่ 7 โมเดลที่เอเจนต์เรียก

Hermes ในกรง sandbox ไม่ได้โหลดน้ำหนักโมเดลเอง มันเป็นโปรแกรมเอเจนต์ที่ส่งคำขอออกไปหา vLLM บนเครื่องโฮสต์

เส้นทางจริงมีสองชื่อของที่เดียวกัน

  • ในกรง Hermes เรียกโฮสต์ว่า https://inference.local/v1/models
  • บนเครื่องโฮสต์ จุดนั้นคือ http://127.0.0.1:8000/v1/models

ดังนั้นแดชบอร์ดที่พอร์ต 18789 เปิดได้แม้โมเดลยังไม่พร้อม เพราะแดชบอร์ดเป็นแค่หน้าเว็บของเอเจนต์ พอส่งข้อความ เอเจนต์ถึงจะยิงไปที่ vLLM ถ้าตอนนั้นชื่อไม่ตรงหรือพอร์ต 8000 ว่าง จะพัง

  1. ตรวจว่าโมเดลภาษาเปิดอยู่บนโฮสต์ ไม่ใช่ในกรง
    llm-status

    ต้องเห็นคอนเทนเนอร์โมเดล running และมี API model ถ้าขึ้น Model: stopped แปลว่า Hermes ไม่มีใครให้ถาม

  2. เปิด Qwen 35B ด้วยคำสั่งที่ขึ้นต้นด้วย start-
    start-qwen35

    อย่าพิมพ์ qwen35-start คำสั่งนั้นเปิดคอนเทนเนอร์คนละตัวชื่อ nemoclaw-vllm อธิบายครบอยู่ที่ หมวดโมเดล · เรื่องที่เกิดจริง

  3. รอ Ready แล้วดูว่ามีชื่อเต็ม

    ต้องเห็น nvidia/Qwen3.6-35B-A3B-NVFP4 เพราะนี่คือสตริงที่ Hermes ใส่ในทุกคำขอ ชื่อใกล้เคียงแต่ไม่ตรงตัวอักษรจะ 404

ขั้นที่ 8 ชื่อโมเดลต้องตรง ทีละขั้น

คิดเป็นสามฝ่าย คนละหน้าที่ ห้ามปน

ฝ่ายทำอะไรมองหาชื่ออะไร
ไฟล์บนดิสก์เก็บน้ำหนักโมเดลประมาณ 22 GBโฟลเดอร์ models--nvidia--Qwen3.6-35B-A3B-NVFP4
vLLM พอร์ต 8000โหลดไฟล์แล้วประกาศชื่อให้คนอื่นเรียกตอนนี้ประกาศทั้งชื่อเต็มและชื่อสั้น
Hermesยิงแชทไปที่ vLLMชื่อเต็ม nvidia/Qwen3.6-35B-A3B-NVFP4 เท่านั้น

Open WebUI ถามรายการแล้วให้คนเลือก จึงใช้ชื่อสั้นได้ Hermes ไม่เลือกจากรายการ มันยิงชื่อที่ตั้งไว้ตรง ๆ

สูตรเก่าของ start-qwen35 ประกาศแค่ Qwen3.6-35B เลยเกิดภาพลวงตาว่า “แชทได้แต่เอเจนต์พัง” ทั้งที่โหลดโมเดลก้อนเดียวกัน

  1. ถาม vLLM ว่าประกาศชื่ออะไร
    curl -s http://127.0.0.1:8000/v1/models | python3 -m json.tool
  2. หาคำว่า nvidia/Qwen3.6-35B-A3B-NVFP4 ในช่อง id

    เจอ = Hermes เรียกได้ ไม่เจอ = ยังใช้สูตรเก่า หรือเปิดโมเดลคนละตัวอยู่

  3. ทดลองชื่อผิดเพื่อจำอาการ 404
    curl -s http://127.0.0.1:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"Qwen3.6-35B-WRONG","messages":[{"role":"user","content":"hi"}]}'

    ต้องได้ข้อความประมาณ The model Qwen3.6-35B-WRONG does not exist รหัส 404 นี่คือสิ่งที่ Hermes เคยได้รับเมื่อชื่อไม่ตรง

  4. ถาม Hermes อีกชั้น
    nemoclaw hermes status

    บรรทัด Model ต้องเป็นชื่อเต็ม บรรทัด Inference (vllm backend) ต้องเป็น healthy

  5. ค่อยเปิดแดชบอร์ดแล้วส่งข้อความในห้องใหม่

    เปิด http://127.0.0.1:18789/ จากเครื่อง DGX อย่าส่งต่อในห้องที่ error 404 ค้างไว้ เพราะข้อความเก่าจะยังโชว์อยู่

อธิบายระดับไฟล์คำสั่งและตัวเลข RAM อยู่ที่ หมวดโมเดล · เรื่องที่เกิดจริง

ปัญหาที่เจอบนเครื่องนี้

แดชบอร์ดเปิดได้ แต่เอเจนต์ตอบ 404

อาการนี้เกิดเมื่อ Hermes เรียกชื่อเต็ม แต่ vLLM ประกาศแค่ชื่อสั้น หรือเปิดโมเดลคนละตัวที่ไม่มีชื่อนั้น ไฟล์โมเดลมีครบ แค่ชื่อไม่ตรง

  1. อย่ารัน qwen35-start ทับ

    ใช้ start-qwen35 อันเดียว คำสั่งนี้จะปิด nemoclaw-vllm ให้ถ้าค้างอยู่

    start-qwen35
  2. รอ Ready จนเห็นชื่อเต็ม

    ต้องมี nvidia/Qwen3.6-35B-A3B-NVFP4

  3. ตรวจ API
    curl -s http://127.0.0.1:8000/v1/models
  4. ตรวจ Hermes
    nemoclaw hermes status

    Inference (vllm backend) ต้อง healthy

  5. รีเฟรชแดชบอร์ดแล้วส่งในห้องใหม่

    อย่าตัดสินจากห้องเก่าที่ error ค้างไว้

ถ้า RAM ดูสูงผิดปกติหลังเปิด Qwen 35B ให้อ่าน ทำไม RAM สูง สูตรปัจจุบันต้องกันประมาณ 35% ไม่ใช่ 82%

เข้า http://127.0.0.1:18789 ไม่ได้

  1. รัน nemoclaw hermes status
  2. ถ้า sandbox หยุด ให้รัน nemoclaw hermes start
  3. ถ้า start แล้วพอร์ตยังเงียบ ให้รัน nemoclaw hermes recover
  4. เปิด URL อีกครั้งจากเครื่อง DGX ไม่ใช่จากมือถือตรง ๆ เพราะเกตเวย์ฟังที่ 127.0.0.1 เท่านั้น

อยากดูว่าเอเจนต์พังตรงไหน

nemoclaw hermes logs --tail 80

ถ้าในล็อกมีคำว่า does not exist หรือ 404 ให้กลับไปตรวจชื่อโมเดลในขั้นที่ 8 ไม่ใช่ไป rebuild sandbox
